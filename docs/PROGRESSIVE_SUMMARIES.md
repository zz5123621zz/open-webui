# 渐进式推理摘要兼容方案

状态：已实现并于 2026-07-25 完成 CI、分阶段生产发布和真实 CPA 验收；
固定镜像、事件时间线、内存与回滚记录见 `docs/VALIDATION.md`。

## 1. 结论

方案可以执行，但它不是“让模型输出原始思维链”。目标是让 CPA 已经收到的
安全推理摘要、网页搜索和工具事件尽快到达浏览器，并在上游没有新内容时只
显示真实的等待状态。

实现需要同时修改两处：

1. La4RainGPT 增加可选请求字段、兼容性状态机、管理员设置、事件持久化和
   前端时间线。
2. 维护一个极小的 CPA fork，只对白名单字段
   `stream_options.reasoning_summary_delivery = "sequential_cutoff"` 放行。

当前 CPA 的 Codex 转换路径会删除整个 `stream_options`。OpenAI Codex 在
2026-07-07 合并的实现则使用上述字段，并消费已经完成的
`reasoning_summary_text.done` 摘要段。因此只修改 La4RainGPT、而完全不改
当前 CPA，实验字段不会到达上游。

参考：

- [Codex PR #31306：sequential cutoff reasoning summaries](https://github.com/openai/codex/pull/31306)
- [CPA PR #2347：删除 Responses 请求中的 stream_options](https://github.com/router-for-me/CLIProxyAPI/pull/2347)
- [CPA Issue #3731：Codex reasoning/thinking 事件排查](https://github.com/router-for-me/CLIProxyAPI/issues/3731)
- [CPA Issue #4265：不可表示的加密 reasoning 占位问题](https://github.com/router-for-me/CLIProxyAPI/issues/4265)

## 2. 不能承诺的内容

- 不展示原始 chain-of-thought、加密推理内容或 Provider 私有状态。
- 不根据用户问题编造“正在分析某某”的思考过程。
- 不保证固定时间内出现第一段语义摘要。上游可能只返回标题式摘要，也可能
  在最终正文前长期没有新的摘要事件。
- 不通过后台测试提示词探测兼容性，不产生隐藏额度消耗。
- 不为了图片生成降低质量，也不改变图片参数的 `auto` 规则。

用户发送后 1 秒内出现计时和真实等待状态；一旦 La4RainGPT 收到上游事件，
应用自身的接收、处理和浏览器展示链路以 1 秒内完成为验收目标。

## 3. 请求路径

La4RainGPT 继续发送：

```json
{
  "reasoning": {
    "effort": "high",
    "summary": "auto"
  }
}
```

当管理员配置为 `auto`、模型具有推理能力、紧急硬关闭未启用且运行状态允许
时，额外发送：

```json
{
  "stream_options": {
    "reasoning_summary_delivery": "sequential_cutoff"
  }
}
```

CPA fork 只接受并转发这一个键和值。它不会把任意 `stream_options` 透传给
上游，也不会改变模型、推理强度、工具或图片参数。若未来 CPA 官方实现该
能力，La4RainGPT 可直接改回官方 CPA 镜像；应用侧字段和管理员开关不依赖
fork 私有响应格式。

## 4. 配置状态与有效状态

管理员持久配置只有两个值：

| 配置 | 含义 |
|---|---|
| `auto` | 允许应用在兼容时请求渐进摘要，建议默认值 |
| `off` | 新请求不携带实验字段 |

另保留部署环境变量形式的紧急硬关闭。硬关闭优先级最高，用于出现未知上游
行为时止损；日常切换使用管理员页面，不需要重启应用或 CPA。

运行状态按“CPA endpoint + 模型”区分：

| 有效状态 | 行为 |
|---|---|
| `unknown` | 下一次符合条件的正常聊天成为唯一探针 |
| `probing` | 探针运行；同键并发请求暂时使用普通模式 |
| `active` | 请求实验字段 |
| `cooldown` | 30 分钟内使用普通模式 |
| `disabled` | 管理员关闭或部署硬关闭 |

“重新检测”只把对应冷却状态清除为 `unknown`。它不会立即调用模型；下一次
正常聊天才进行探测。每个回答任务在开始时固定当时的管理员配置；配置变化
只影响之后开始的新回答，不取消或重写正在生成的回答。

运行状态保存在进程内，重启后重新变为 `unknown`；管理员配置和审计记录保存
在 SQLite。这样不会把一次短暂兼容故障永久固化。

## 5. 降级与重试边界

只有同时满足以下条件时允许透明兼容降级：

1. Provider 尚未返回成功 HTTP 响应，也没有任何 SSE 事件；
2. 返回的是可解析的请求拒绝；
3. 错误明确指向 `stream_options` 或
   `reasoning_summary_delivery` 不受支持；
4. 当前请求尚未进行过兼容降级。

应用随后仅重试一次，并移除实验字段。该键进入 30 分钟 `cooldown`。

一旦 Provider 返回成功响应或任意 SSE 事件，该尝试视为已接受。后续断流、
网络错误或上游失败只保存为部分/失败回答，由用户手动重试；应用不会暗中
生成第二个回答请求。这能避免重复额度、重复网页搜索、重复图片生成或其他
工具副作用。

现有代码有两处必须随实施收紧：

- `startResponseWithNetworkRetry` 会在网络错误时自动重发 POST；网络错误无法
  证明第一次请求未被上游接受，因此应删除这次自动重发。
- 当前上下文窗口处理允许在已建立 SSE、但尚无可见输出时重新压缩并重发；
  新边界只保留明确 HTTP 拒绝后的安全重试，不对已接受的流自动重发。

本地上下文预压缩继续保留。明确的、成功响应前返回的上下文长度 HTTP 拒绝
仍可在强制压缩后安全重试，因为 Provider 已明确拒绝了第一次尝试。

## 6. 事件模型与历史记录

当前前端会把同类型的 reasoning 文本并入第一张卡片。新实现以 Provider
标识为准保存和渲染：

- 推理摘要键：Provider item ID + summary index；
- 工具事件键：Provider call/item ID；
- 显示顺序：首次收到事件的顺序；
- 增量更新：只更新相同键对应的卡片；
- 刷新恢复：从持久化 parts 原样恢复卡片顺序。

持久化内容：

- Provider 实际返回的安全推理摘要段；
- 搜索词、清洗后的网页地址、网页标题；
- 工具类型、状态和 Provider 提供的安全结果；
- 已经生成并保存的正文、引用和图片。

不持久化内容：

- “已运行 37 秒”等客户端计时；
- SSE 心跳；
- “等待上游更新”等临时状态；
- 原始请求头、Cookie、内部 Provider 字段；
- `encrypted_content` 或不可解释的 reasoning 占位内容。

重新打开会话时只恢复真实的 Provider 证据，不重新播放等待动画。

## 7. 网页证据清洗

清洗发生在展示和入库之前：

- 只接受 `http`、`https`；
- 删除 URL 用户名、密码和 fragment；
- 删除 `utm_*`、`fbclid`、`gclid` 等跟踪参数；
- 删除 `token`、`access_token`、`api_key`、`signature`、`session` 等
  疑似凭据参数；
- 保留普通导航查询参数，避免分页和内容链接失效；
- 搜索词和页内查找词按现有长度上限截断；
- 不接受 Header、Cookie、授权值或任意 Provider JSON。

极少数依赖签名参数的临时链接可能因此不可点击，这是防止凭据进入七天留档
和备份的有意取舍。

## 8. 管理员控制

新增一个仅管理员可见的“渐进式推理摘要”设置卡：

- 配置选择：`自动` / `关闭`；
- 有效状态：可用、检测中、暂时不兼容、已关闭；
- 显示最近检测时间和冷却剩余时间；
- `重新检测` 按钮；
- 明确提示重新检测将在下一次正常聊天发生。

后端只开放枚举设置，不接受 CPA 密钥、任意 JSON、模型映射或其他 Provider
配置。写操作沿用登录 Session、管理员授权、Origin 与 CSRF 防护，并记录
操作者、旧值、新值、时间和重新检测动作。管理员权限不会扩展为修改其他
用户的会话。

## 9. 数据与 API 变更

预计新增：

- SQLite `service_settings`：枚举键、枚举值、更新时间、更新人；
- SQLite `service_setting_audit`：操作者、动作、旧值、新值、时间；
- 管理员读取/修改设置与触发重新检测的窄接口；
- reasoning part 的稳定 Provider identity 与 section index；
- 进程内的并发安全兼容状态表和单探针控制。

迁移必须保持现有历史消息可读。旧 reasoning part 没有 section identity 时
按一张旧式摘要卡显示，不回填或猜测段落。

## 10. 前端表现

聊天时间线使用中文标签并区分两类信息：

- Provider 证据：推理摘要、正在搜索的词、访问网页、工具状态；
- 临时活动：等待模型、已运行秒数、等待下一条上游事件。

每个 Provider 摘要段独立成卡，流式追加时不抢夺页面滚动位置。用户向上
滚动后保持当前位置；回到底部后才恢复自动跟随。桌面和手机均显示同一信息，
手机端允许卡片内容换行、网址省略和点击展开。

## 11. 资源与并发影响

兼容状态表只有少量“endpoint + 模型”记录，计时在浏览器完成；正常情况下
不会显著增加后端内存。持久化增加的是 Provider 本来已经发送的小段摘要和
工具证据，不保存心跳或逐秒计时。

实施不改变：

- 每用户最多 2 个同时运行请求；
- 全应用最多 4 个同时运行请求；
- La4RainGPT 容器 320 MiB 硬上限；
- CPA 请求体 50 MiB 硬限制；
- 图片质量与 `auto` 参数。

CPA fork 仍是独立小容器/镜像。发布后需要重新测量 La4RainGPT 和 CPA 的
`memory.current`、`memory.peak`，但该功能本身没有需要常驻大缓存的新组件。

## 12. 验收

CI 使用模拟 CPA 流确定性验证：

1. 多个摘要 section 按顺序逐条出现并在刷新后保持；
2. 搜索词、网址和工具阶段正确显示中文；
3. 收到事件到前端处理完成不超过 1 秒；
4. Provider 静默时只有计时和事实状态，不生成虚构摘要；
5. 明确的不兼容 HTTP 拒绝只降级一次；
6. 成功响应或任意 SSE 之后绝不自动重发；
7. 30 分钟冷却、单探针和管理员重新检测无竞态；
8. 普通用户无法读取或修改服务设置；
9. URL 凭据、跟踪参数和疑似 secret 不进入数据库；
10. 桌面与手机 Playwright 场景通过；
11. 旧历史消息和现有文本、图片、搜索、压缩流程不回归。

生产验证：

- 先以管理员设置 `off` 部署并检查普通聊天；
- 切换 `auto`，使用真实 CPA 观察事件时间线；
- 验证管理员开关无需重启；
- 验证不支持模型的单次降级和冷却状态；
- 检查四请求限制、容器健康、错误日志和内存峰值；
- 把通过结果和固定镜像 digest 写入 `docs/VALIDATION.md`。

Go、前端构建、Playwright 和镜像扫描继续只在 GitHub Actions 运行，不在
1 GiB VPS 上启动 Go 测试或编译进程。

## 13. 发布与回滚

发布顺序：

1. CPA fork CI 构建并固定镜像 digest；
2. 在不改变现有 CPA secret 与额度的前提下替换 CPA 镜像；
3. La4RainGPT CI 构建并固定应用镜像 digest；
4. 数据库备份；
5. 应用以 `off` 部署；
6. 健康检查后由管理员切换 `auto`；
7. 完成真实聊天、错误降级和内存观察。

回滚优先级：

1. 管理员立即切换 `off`，新请求恢复普通模式；
2. 必要时启用应用部署级硬关闭；
3. 回滚 La4RainGPT 旧 digest；
4. CPA fork 有问题时回滚官方 CPA 旧 digest。

关闭渐进摘要不会删除已经保存的安全摘要或工具证据，也不会改变正在运行的
回答。
