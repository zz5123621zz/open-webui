# 2026-07 移动阅读与本地搜索体验评审

## 目标与约束

本轮只采用静态前端、CSS 和既有 Responses `instructions` 能完成的改进，
不增加常驻后端服务、搜索聚合器、语音链路或新的数据库状态。目标设备以
320–430 px 手机为先，同时保持桌面长回答的可读行长。

## Before / After

| Before | After | Why |
|---|---|---|
| 用户与助手共用头像网格，用户气泡占满剩余列 | 用户消息按内容靠右，桌面最多 680 px、手机最多 88%；手机助手使用完整内容栏 | 明确说话双方，增加回答和富内容的有效宽度 |
| Markdown 表格直接把 `table` 变成滚动块 | 表格进入带可访问名称和键盘焦点的独立滚动容器，只在实际溢出时提示左右滑动 | 防止页面横向溢出，同时让触控和键盘用户都能查看完整列 |
| 代码、公式、长链接、引用和原生 `details` 仅有零散样式 | 统一设置最大宽度、局部滚动、换行、移动字号和边界 | 表格以外的模型输出也不会撑破 320/375 px 页面 |
| 完成的工具调用仍占用较高卡片 | 工具卡片缩短图标和内边距，查询允许完整换行，来源仍在回答附近展开 | 提高长搜索过程的信息密度，不隐藏用户关心的搜索内容 |
| Responses 只要求中文回答，没有本地检索偏好 | 中国本地实体先用含城市/区县的中文查询，优先官方、本土地图和生活服务来源，并交叉核验营业信息 | 降低同名境外实体和非本土网页喧宾夺主的概率 |
| 首次登录直接进入空白聊天页 | 四步可跳过指南介绍模型、推理档位、会话管理和输入/过程卡片；头像菜单可重新打开 | 降低首次使用成本，状态仅存每个用户的浏览器 `localStorage` |

## 搜索边界

“中国优先”是意图相关的来源优先级，不是域名硬封锁：

- 中国本地饭馆、地点、政策、活动等先查中文本土来源；
- 地图、点评和社交内容只作为发现或用户评价，不能冒充官方事实；
- 地址、营业时间等实用信息尽量由官方来源或两个近期独立本地来源核验；
- 同名实体且缺少城市时先要求补充位置；
- 全球主题继续使用最合适的国际来源；本土可靠来源不可得时明确说明。

这种做法不增加额外模型请求，也避免硬编码域名列表导致全球问题质量下降。
最终检索范围仍受 CPA 上游搜索能力和目标网站可访问性影响。

## 资源影响

- 新手指南：一个按需渲染的 Svelte 组件与少量 CSS，完成状态留在浏览器；
- 富文本适配：每个有表格的回答增加一个轻量 DOM 包装和共享
  `ResizeObserver`，没有服务端开销；
- 搜索本地化：扩充现有 Provider 指令，不增加 API 调用或常驻进程；
- Docker 内存上限、SQLite 模型、并发限制和存储配额均不变。
